# 子任务④ 真机走查记录（2026-08-02）

`prd.md` 的 U1–U14 逐条走查。走查在 dev 模式的桌面端上进行，全部经真实界面操作
（点按钮、敲回车、改磁盘文件），不是调函数模拟。

## 走查手段与它的一处折衷

桌面端由 `REMOTE_DEBUGGING_PORT=9222 V8_INSPECTOR_PORT=5858 pnpm desktop` 起，
renderer 走 CDP `Runtime.evaluate` / `Page.captureScreenshot` 驱动与取证，
main 走 node inspector。

**两处原生对话框做了替身，理由与影响如下：**

| 对话框 | 处理 | 为什么 | 对结论的影响 |
|---|---|---|---|
| `showOpenDialog`（选目录/文件） | 注入返回路径 | osascript 发不了按键（报 1002），原生选择框没法输入路径 | 无。被替换的只是「用户在 Finder 里点哪个文件」，选完之后的整条链路全是真的 |
| `showMessageBox`（付费确认） | 记录完整选项并按队列应答 | 走查中途屏幕锁定，原生框既截不到也点不了，**且会把 main 卡在嵌套 run loop 里**（连 CDP 都不响应，实测卡死过一次） | U13 的「框长什么样」由捕获到的完整选项作证（见下），**没有**这个框的照片 |

`showMessageBox` 的调用本身没有被绕过：它确实在发起生成之前被调用，
按「取消」时确实一页都没生成（下有实测）。**唯一没有直接证据的是这个框在屏幕上的样子。**

批量生成前捕获到的 `showMessageBox` 选项（原样）：

```json
{
  "type": "warning",
  "title": "确认批量生成",
  "message": "将调用最多 4 次图像生成",
  "detail": "规格共 4 条；已生成且未改动的条目会被跳过，因此实际次数可能更少。按次计费且不可撤销，生成后每页都需要你逐张确认源图。",
  "buttons": ["生成（最多 4 页）", "取消"],

  "cancelId": 1

```

按「取消」（response 1）：**deck 目录都没建出来**，一次图像调用都没有。
按「生成」：4 页依次生成。默认焦点与 Esc 都落在取消上。

次数确实跟着规格走：换成只有 1 条的规格文件追加时，捕获到的是
「将调用最多 1 次图像生成 / 生成（最多 1 页）」。

单张重新生成为二次点击：第一次点击按钮文案变「确认重新生成？」并展开可选说明框，
title 变「再点一次即调用图像生成（按次付费）」；4 秒无操作自动复位（实测复位过两次）。

**「最多 N 次」不是保守措辞**：同一天对同一份规格再点一次「新建」，落点算出来是同一个

`design.md` 之外的判断④（见 START.md）由此被证实。

## 走查查出并修掉的 7 个缺陷

前 5 个是 ④ 的交付缺口，第 6 个是踩到既有实现里的一条错规则，第 7 个是修第 6 个时
自己引入又被走查抓回来的。

### 1. 顶栏下拉仍是「从图片目录创建…」，另外两档来源无路可走

deck 打开状态下，新建 deck 的唯一入口是顶栏下拉，而它直接开图片目录框。
想从 PDF 或内容规格新建的人只能先关掉当前 deck——正是父任务点名禁止的
「三次零散增补」。

改法：该项改名「新建 Deck…」，只负责打开来源选择模态；模态开关从 ConsolePage 的局部
state 提到 `ui-store`（两个入口分处两棵子树），且存的是**目标档**（`new` / `append`）
而不是布尔，否则顶栏那条路会被「当前有没有 deck」反推成追加。
锁：`workspace-menu.test.ts`「create 只打开来源选择模态，不开目录框」。

### 2. 切换工作区后活动日志恒为「暂无记录」

**这条是既有缺陷，不是 ④ 引入的**——打开任何一个有历史的 deck 都会空（实测
214 条记录的 deck 打开后显示「暂无记录」）。但 U4 的「关掉后能从活动日志重新打开
同一份报告」直接压在它上面，必须在 ④ 修掉。

根因：真实时序是 `openDeck` 落好新 deckPath → React 冲刷 effect → **effect 已经发出
`load(新)`** → 才轮到 `resetOtherStores()`。`activity-store.reset()` 按序号一刀切作废
（`listSeq += 1`），把这次**已经属于新 deck** 的请求也连坐掉，而之后没有任何东西会
再发一次。全程不报错。

改法：作废改为按身份——`reset(nextDeckPath)`，`load` 落地前既要是最后一次请求、
也要属于当前 deck。变异验证：把 `listSeq += 1` 加回去，新增用例转红。
这条同时回写了 `state-management.md`——那份 spec 当时写的正是「`reset()` 里要一并
作废在途请求（`listSeq += 1`）」，规则本身有缺口。

### 3. 建页任务写了活动记录，但界面不重拉

追加场景不换 `deckPath`，没有任何 effect 会重载日志，于是抽取报告一关就再也找不回来，
而磁盘上那条记录一直在。既有流水线之所以没事，是因为 run-store 在 `run-done` 里显式
重拉了一次；新链路照抄了「写」，没照抄「拉」。

改法：`runSourceTask` 收尾统一 `reloadActivity()`，失败路径同样（`recordFailure` 也写了记录）。

### 4. 建页任务被互斥挡下时，界面什么都不显示

`accepted: false` 掉在两套呈现的缝里：完成面板与抽取报告只认 `accepted`，
错误条只认抛出来的异常。用户点完「追加页面」只看到模态一关，界面纹丝不动。
编排层甚至写着「被互斥挡下不是丢弃，它要照常报给用户」——意图在，呈现不在。

改法：判据抽成 `sourceTaskBlockedReason()`（理由为空也要出一句话，不静默），
建页任务条以 `state-stale` 呈现并配「知道了」。用 stale 不用 failed：没有任何东西失败，
是「现在不能跑」。

### 5. 生成页全部确认完之后，审片视图连同「重新生成」再无入口

三个入口分别是待办组标题、生成完成面板、待确认页的卡片直达——**全部以「还欠一次确认」
为前提**。一旦某个 deck 的生成页全部确认完，待办组消失、卡片改进复核页、完成面板早已
关掉，「按规格重新出一张图」在界面上彻底没有入口。与 2026-07-30 那条「重做底图随确认页
一起消失」是同型错误，`accept-gate.ts` 里那张表甚至已经写明 `sourceReviewReachable`
是给「卡片是否直达此视图」用的，实现却用了 `awaitingSourceConfirm`。

改法：已确认的页点卡片仍进复核页（那才是它接下来的活），入口补在**单页工具栏**上——
`sourceReviewReachable && !awaitingSourceConfirm` 时给一个 ghost 的「源图审片」。

### 6. IPC 错误把通道名与类名怼在用户脸上

错误条上出现的整句是
`Error invoking remote method 'deck:source-task-start': FoundationError: PDF 中没有…`。
领域错误（页码范围非法、PDF 里没有 16:9 页）本就该原样回显（R3），前面挂两层壳
等于把「照常显示原因」打了折。改法：`lib/ipc-error.ts` 只剥外壳、剥不掉就原样返回。

### 7.（自己引入）新建后完成面板与「去确认」整个不出现

修缺陷 2 时给 `resetOtherStores` 加上了 `useSourceTaskStore.reset()`（换 deck 后上一个
deck 的错误条还挂在新 deck 顶上，确实该清），结果把**触发这次切换的那个结果**一起清了。
两处都要改：

- `runSourceTask` 把 `onResult` 挪到切换/刷新**之后**——结果本就属于切换后的那个 deck；
- 完成面板的判据是 `kind === "generate" && lastResult`，两半由两次不同的写入产生，
  `kind` 来自进度事件、会被清零带走，因此收尾补写一次 `kind`。

顺带发现「新建」并不保证换了 deck（同规格同日再建一次落回同一个目录），
`deckPath` 没变则 effect 不会重跑，所以 `reloadActivity()` 两条路都要调。

## 观感与遗留（不改，记录在案）

1. **「全部 N 页都已推进到位」对未开始的页不准确。** 新建出来的 deck 一页都没跑，
   待办筛选却说「都已推进到位」。这是 M4 起的既有文案，与 ④ 无关，也不影响任何判据。
2. **START.md 留的那个问题**：批量生成刚完成时新页全部卡在 accept-source，
   此刻「处理全部」是否该禁用。走查结论是**不必禁用**——按下去闸门会如实把它们拦在
   `accept-source`，界面随即在待办队列里列出「待确认源图」，用户看得到发生了什么；
   而完成面板的「去确认」已经把正路指出来了。禁用一个「按了也不会出错、只是没进展」的
   按钮，反而要再造一条禁用理由文案。
3. `SlideCard` 里「已移除」徽标那一支在控制台取不到（控制台不渲染移除页），
   属既有的防御性代码，本次未动。
