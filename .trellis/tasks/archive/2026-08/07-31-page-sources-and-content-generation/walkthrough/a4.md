### 观察 ① 旧 deck 的复核文档会撞上后加的校验规则，`deck run` 报错并停住

**现象**（首次 `deck run` 时暴露，我没碰过 page-02）：

```
page-02 (…): ocr → review → validate-review — 停在 validate-review (validation-failed)
```

```bash
node apps/cli/dist/index.js slide validate-review ~/test/a4-regression-2026-08-02/slides/page-02
# [error] block-045 includeInMask：版式目标文字必须参与 mask，否则导出后文字会与背景重影
#         (LAYOUT_TEXT_MUST_BE_MASKED)
# EXIT=1
```

**根因**：复核文档一字未改（`documentSha256` 前后同为 `26b07999…`），变的是规则版本：

| 时间 | rulesVersion | status |
|---|---|---|
| 2026-07-25（deck 产出时） | `review-validation-v1` | passed |
| 2026-08-02（本次） | `review-validation-v2` | failed |

规则由 `e03af4a`（2026-07-26，**M4 阶段 A**「堵死 layout_text 重影漏洞」）引入，
比这份 deck 晚一天。判定逻辑在 `packages/core/src/text-blocks.ts`
（`LAYOUT_TEXT_MUST_BE_MASKED`）。

**为什么不算缺陷**：① 失败是**响亮的**——非零退出、指名 blockId 与 field、
说清后果（重影），完全不是静默失败；② 它保护的是真实缺陷，放行才是错的；
③ `--strict` 导出不受影响（旧 `accept-pptx` 仍 completed），A4 的三个动作都成立；
④ 属 M4 的规则收紧，与 M5 的来源契约无关。

**补救成本很低**，本走查按规则自身的说法改了一个布尔量即通过：

```bash
python3 -c "…block-045 includeInMask = True…"
node apps/cli/dist/index.js slide validate-review <page-02>   # 校验通过：错误 0，警告 0
```

**留给主会话的判断**：这是 A4「无迁移步骤」的一个边角——比 2026-07-26 更早的 deck
想继续处理，需要一次人工内容修正（不是迁移程序，但也不是零动作）。
若要收口，可考虑在 `deck run` 的失败提示里点明「该页复核文档产出于规则 v1，
当前规则 v2 新增了 X 条」，让用户一眼知道这不是自己改坏的。

### 观察 ② clean 自动检查恒报「尺寸异常」，因为期望值写死 2048×1152

`accept-final` 输出里的「clean：尺寸异常」来自 `clean-003/record.json`：

```json

                      "expectedWidth": 2048, "expectedHeight": 1152,

```

而这份 deck 的**源图本身就是 1672×940**（`sips` 独立复核 `inputs/source.png`），

**非本次引入**：备份里 2026-07-25 的 `clean-001` / `clean-002` 记录同样 `ok: false`。

`aspectRatioOk: true`、`residualForegroundPixels: 0`，实质无害。

## 7. 走查手法上的一个坑（不是产品问题，供后续复用）

手改 `text-blocks.json` 时只改 `text` 不改 `lines`，PPTX 会照旧文字合成：
合成侧取文规则是「优先 `lines`，缺省回退整段 `text`」
（`apps/desktop/src/renderer/components/final/CompositePreview.tsx:142-143` 注明与
`synthesize.ts` 同规则）。第一次重跑时我就踩了这个——`pptx-002` 的
`reviewDocumentSha256` 确实是新文档、`slide.pptx` 确实换了 sha，
但 `slide1.xml` 里仍是「极大」。校验也不会报（没有 text/lines 一致性规则）。
桌面端编辑器两个字段一起写（`BlockTextEditor.tsx:52-58`），所以真实用户路径无此问题；
**脚本驱动走查时必须两个字段一起改**。
