# 发现的缺陷

## 缺陷 1（A2 直接命中）：`deck status` 的人类输出不显示来源，逐页来源只有 `--json` 有

**现象**：A2 要求「`deck status` … 能逐页看出来源」。11 页混合来源的 deck 上：

```
$ node apps/cli/dist/index.js deck status ~/test/a23-mixed-2026-08-02
ppttest-2026-07-25 (11 页)
  完成: 11/11
```

来源一个字都没有。有页在跑时也只多一行 `进行中: page-03 (assist-review)`，同样无来源。

**复现**：`node apps/cli/dist/index.js deck status ~/test/a23-mixed-2026-08-02`
（对照 `--json` 里每页都有 `sourceKind`）。

**根因**：`apps/cli/src/deck/status.ts:246` 的 `formatDeckStatus` 只渲染
`完成 / 进行中 / 失败 / 规格漂移 / 规格失联` 五种行，**从不读 `slide.sourceKind`**。
数据层没问题（`status.ts:199` 已从 `workspace.manifest.source.kind` 取到并放进
`DeckSlideStatus.sourceKind`，字段声明在 `status.ts:66`），断在展示层。桌面端那一半是好的（见下方「来源列取值链」）。

**建议修法**：`formatDeckStatus` 增加逐页来源。两条约束照抄桌面端已定的口径：
① 文案用 `SOURCE_KIND_LABELS` 的同一组词（导入 / 抽取 / 生成），不在 CLI 另写一份；
② 来源是常态信息，不要放进 `失败:` / `进行中:` 这类「要你管」的行里。
最省事且不撑爆输出的形态是加一行分布汇总，例如
`  来源: 导入 4 / 抽取 6 / 生成 1`，逐页明细仍留给 `--json`；
若要满足 A2 字面的「逐页」，则需要一份逐页表格（页数多时会很长，建议加 `--verbose` 门槛）。
**这条要不要算 A2 通过，是产品口径问题，需要主会话拍板**——数据在、桌面端也在，
只有 CLI 的默认输出没有。

## 缺陷 2（走查中被 snap diff 逼出来）：`deck run` 对已完成的 deck 不幂等，每跑一次重写每一页

**现象**：11 页全部 `report completed`、无一页 stale 时，再跑一次
`deck run --confirm-api --confirm-upload`，**11 页的目录 shasum 全部改变**：

```diff
< HASH page-01 95985d3c6563786355c119ba2a079ffd5ebd40ea
…
> HASH page-01 641dd0f2c13c6bd5918abf37126df4eb120b35fb
（11 行全变，summary 无变化）
```

逐文件定位到每页只有三个文件被改写：

```diff
< …/page-10/manifest.json
< …/page-10/stages/report/report.json
< …/page-10/stages/review/validation.json
```

内容比对：`report.json` 只有 `generatedAt` 变、`validation.json` 只有 `checkedAt` 变，
其余逐字段相同；`manifest.attempts` 里 **`report` 已累积 9 条，其它每个阶段各 1 条**。

**复现**：

```bash
tools/snap.sh <一个 11 页全完成的 deck> /tmp/i1.txt
node apps/cli/dist/index.js deck run <同一 deck> --confirm-api --confirm-upload
tools/snap.sh <同一 deck> /tmp/i2.txt
diff /tmp/i1.txt /tmp/i2.txt     # 每一页的 HASH 行都变
python3 -c "import json,collections;print(collections.Counter(a['stage'] for a in json.load(open('<deck>/slides/page-10/manifest.json'))['attempts']))"
```

**根因**：`apps/cli/src/slide/run-from.ts` 的执行循环里，
「状态已是 `completed` 就跳过」这条守卫**只写在三个分支上**——
`assist-review`（:132）、`clean`（:189）、`accept-pptx`（:210）。
其余分支无条件调用各自的 run 函数：

- `ocr`（:125）、`review`（:128）、`mask`（:180）、`pptx`（:183）
  —— 它们函数内部有 `isStageReusable` 指纹复用，产物字节不变、attempt 不增，**代价只是空跑**；
- **`report`（:186）没有任何复用**，每次都重写 `report.json`（新 `generatedAt`）
  并**追加一条 attempt**；
- `validate-review`（:153）是瞬态阶段（不写 `stages`），同样每次重写 `validation.json`。

这与 `.trellis/spec/backend/contracts.md`〈阶段落库与强制重跑〉写死的
「`run-from.ts` 各阶段守卫 = `stageState(...)?.status !== "completed"`」不一致
—— 规范说的是**各**阶段，实现只做了三个。

**后果**：① `attempts` 数组随 run 次数无界增长（本次走查跑了 9 轮，`report` 就有 9 条），
读 attempt 做统计的地方（桌面端单页详情按 attempts 聚合）会被灌水；
② **打穿「已完成页零变化」这条不变量**——用户换一页源再跑一次 `deck run`，
所有页的产物字节都变了，A3 这类「其它页没被动过」的核查在真实使用序列下无法直接成立
（本次是靠「换源后先 snap、再跑下游」把两件事拆开才验干净的）；
③ 与《静默失败诊断指南》里「毫秒级完成 ≠ 成功」的诊断法冲突：现在**已完成的页每次都会
产生一条 report attempt**，`report` 有新 attempt 不再能说明这一轮真做了事。

**建议修法**：给 `report` 分支补上与 `clean` / `assist-review` 同形的守卫
（`stageState(workspace.manifest, "report")?.status !== "completed"`），
这是唯一会累积状态的那个。`ocr` / `review` / `mask` / `pptx` 补守卫是纯提速，可选。
`validate-review` 是瞬态阶段、天然无状态可判，若要止住 `checkedAt` 抖动，
判据应取「`documentSha256` 与当前 `text-blocks.json` 实时 sha 相同则不重写文件」，
而不是给它造一个假的阶段状态。
测试要点按 spec 的口径写：**断言落库后的持久状态**——
跑两次 `deck run`，断言 `attempts` 里 `report` 仍只有一条、`report.json` 逐字节不变。

# 顺带交付：桌面端总览「来源列」的取值链（主会话要用）

单一事实源是 slide manifest 的 `source.kind`，CLI 与桌面端同源，不存在两份口径：

| 层 | 文件:行 | 做什么 |
|---|---|---|
| 耐久层 | slide `manifest.json` 的 `source.kind` | 唯一事实源（design §1：来源属于 slide，deck 不冗余） |
| CLI 派生 | `apps/cli/src/deck/status.ts:199` | `sourceKind: source.kind` 写进 `DeckSlideStatus`（字段声明 `:66`） |
| main IPC | `apps/desktop/src/main/ipc/deck.ts:64` | 直接调 CLI 的 `deckStatus`，在其上叠加 manifest 聚合 |
| IPC 类型 | `apps/desktop/src/main/ipc/channels.ts:35` | `readonly sourceKind: SlideSourceKind \| null` |
| 文案单点 | `apps/desktop/src/renderer/lib/source-view.ts:21`（`SOURCE_KIND_LABELS`）、`:34`（`sourceBadgeLabel`） | 导入 / 抽取 / 生成，三档中文短词只此一份 |
| 渲染 | `apps/desktop/src/renderer/components/console/SlideCard.tsx:143` + `:248-265` | 缩略图**左上角**徽标；与「已移除」徽标互斥，**刻意不上色** |
| 另一处消费 | `apps/desktop/src/renderer/pages/SourceReviewPage.tsx:419` | 审片视图顶部同样用 `SOURCE_KIND_LABELS` |

主会话核对时：总览卡片左上角应逐页显示「导入 ×4 / 抽取 ×5 / 生成 ×1」
（page-05 已在 A3 中由抽取换成导入），page-11 另有 `specDrift: in-sync`（不显示漂移标注）。
